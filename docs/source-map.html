Architecture reference

What every function does, and how a message actually flows through it

wangscode is two systems sharing one process: a genuine multi-turn chat host (streams tokens, prompts for tool permission, behaves like Claude Code) sitting on top of a deterministic, gate-driven feature-build pipeline that the chat can dispatch into but never talks its way around. This map traces every file — what it owns, what calls it, and what it calls next.

23 source files · 1,850 LOC @anthropic-ai/claude-agent-sdk oxlint + oxfmt

01Two layers, one process

src/*.ts is the interactive shell: it owns the terminal, the model conversation, and the human. src/pipeline/*.ts is the part that used to be its own CLI (agentic-feature-loop) before being merged in — it owns the 8-phase feature build and never lets the model's own judgment decide whether a phase is "done." The chat layer calls into the pipeline; the pipeline never calls back into the chat layer.

02Starting a chat session

One query() call for the whole process lifetime. AsyncInputQueue is the trick that makes that possible — readline's line events push into it, and the SDK pulls from it as an async iterable, so the session never restarts between messages. 

sequenceDiagram
    participant U as Terminal
    participant CLI as cli.ts
    participant REPL as repl.ts
    participant SESSOPT as session-options.ts
    participant Q as AsyncInputQueue
    participant SDK as query() session
    participant FBC as FeatureBuildController

    U->>CLI: npx wangscode --project=.
    CLI->>REPL: runRepl({ cwd })
    REPL->>FBC: new FeatureBuildController(rl, cwd)
    REPL->>SESSOPT: buildSessionOptions(cwd, canUseTool, FBC)
    SESSOPT-->>REPL: Options (agents, plugins, mcpServers, persona)
    REPL->>SDK: query({ prompt: inputQueue, options })
    REPL->>U: "> " prompt
    loop every keystroke line
        U->>REPL: rl 'line' event
        REPL->>FBC: handleLine(line)
        alt busy, awaiting answer, or /create-feature
            FBC-->>REPL: handled = true
            REPL->>U: print result, re-prompt
        else ordinary chat message
            REPL->>Q: push(line)
            Q->>SDK: yielded as SDKUserMessage
            SDK-->>REPL: stream_event / assistant / result
            REPL->>U: renderMessage() streams tokens
        end
    end

repl.ts § runRepl() — the host-intercept check always runs before a line reaches the model.

03Two doors into the same feature build

The model can decide to call create_feature mid-conversation, or the user can type /create-feature directly — both paths converge on FeatureBuildController.start() before anything touches the pipeline. 

flowchart LR
    subgraph Entry["Two entry points"]
        M["Model calls the\ncreate_feature tool"]
        S["User types\n/create-feature or /cf"]
    end
    M --> FBT["feature-build-tool.ts\ncreateFeatureBuildMcpServer()"]
    S --> SC1["slash-commands.ts\nrunInteractivePrompt()\n(asks 6 questions)"]
    FBT --> C["FeatureBuildController.start()"]
    SC1 --> C
    C --> P["runFeatureBuildPipeline()\npipeline/run-build-feature.ts"]
    P -->|"needs_input"| Pend["controller stores pending\n{featureSlug, project}"]
    Pend -->|"user's very next message"| Ans["FeatureBuildController.answer()"]
    Ans --> P
    P -->|"completed / failed"| Done["renderResult() → printed verbatim"]

Once a build is needs_input, the user's next plain message is intercepted by handleLine() and never reaches the model — no re-formatting a resume call.

04Inside the pipeline: 8 phases, one retry rule

run-build-feature.ts walks a cursor through CODE_PHASES. A gate failure doesn't just retry the phase that failed — bug-routing.ts classifies which phase actually owns the bug and rewinds the cursor there, un-completing everything after it (requirements is never rewound). 

flowchart TD
    R["requirements\n(own clarify loop)"] -->|bundle ready| DL["data-layer"]
    DL -->|"pnpm type-check"| TC["test-contract"]
    TC -->|"spectra sync-types + type-check"| UI["ui-slice"]
    UI -->|"grep: every selector has aria-label/id"| CN["connect"]
    CN -->|"type-check + dependency-rule grep"| E2E["e2e-run"]
    E2E -->|"spectra run + spectra test"| LT["lint"]
    LT -->|"type-check + pnpm lint"| RV["review"]
    RV -->|"0 BLOCKER findings"| Done(("completed"))

    DL -.fail.-> Retry{{"classify + rewind\n(bug-routing.ts)"}}
    TC -.fail.-> Retry
    UI -.fail.-> Retry
    CN -.fail.-> Retry
    E2E -.fail.-> Retry
    LT -.fail.-> Retry
    RV -.fail.-> Retry
    Retry -->|"retries ≤ maxRetries (3)"| DL
    Retry -->|"retries exceeded"| Failed(("failed\n+ escalation"))

    R -.gap unresolved.-> NI1(("needs_input"))
    DL -.interactive mode, not yet approved.-> NI2(("needs_input"))

Only data-layer, test-contract, ui-slice, connect, and review call the model (agent-runner.ts). e2e-run and lint are gate-only — a real command decides, nothing else.

05What never changes

  • Gates are commands, never opinions.Every phase advance is gated by tsc, oxlint/pnpm lint, a grep, or a real e2e run (gates.ts) — a model's structured output is validated by Zod (schemas.ts), never trusted as "done."
  • Control flow lives in code the model can't talk around.agent-runner.ts is the only file that calls the model. run-build-feature.ts is the only file that decides what runs next.
  • State is a file, not memory..feature-build/<slug>/state.json makes every needs_input pause and resume call safe and idempotent — it's how a chat message days apart still resumes correctly.
  • Subagents and skills ship inside this package.Options.agents (subagents.ts) and Options.plugins (wangs-plugin/) mean a consumer repo carries zero .claude/agents or project-specific .claude/skills — updating wangscode updates them.
  • A pipeline crash can never take the chat down.FeatureBuildController.start()/.answer() catch everything and return a synthetic hostFailure result instead of letting an exception escape.

A pull-based queue: buffers a pushed message if nothing's waiting, or resolves a waiting next() immediately. This is the entire trick that keeps the SDK session "ongoing" instead of one-shot.

Class member Does

[Symbol.asyncIterator]() Shifts a buffered message, or returns a promise that resolves the next time .push() or .close() fires.
